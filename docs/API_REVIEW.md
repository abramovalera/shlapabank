# Ревью API ShlapaBank

Пробежался по всем роутерам (`backend/app/routes/*.py`). Ниже — что можно почистить, что переименовать, что добавить.

## Что убрать / переименовать

**1. Дубли по «test/helper»-эндпоинтам.**
Сейчас пополнить/уменьшить/обнулить счёт можно двумя путями:
- `POST /accounts/{id}/topup` (нормальный, требует OTP)
- `POST /helper/accounts/{id}/increase` / `/decrease` / `/zero` (без OTP, для тестов)

Они делают почти одно и то же. Предлагаю:
- Оставить `POST /accounts/{id}/topup` как единственный «настоящий» способ пополнения.
- Перегруппировать helper-эндпоинты под явный префикс `/api/v1/dev/*` (сейчас `/helper/*`). Так сразу видно «это только для отладки». Плюс скрыть их из документации в prod (через `include_in_schema=False` под флагом env).

**2. `POST /helper/clear-browser` — странный эндпоинт.**
Возвращает `{detail: "clear_browser", redirect: "/login"}`. Это UI-задача, серверу не нужна. Удалить.

**3. `POST /admin/restore-initial-state` — потенциально опасный.**
Понятно зачем нужен, но название неоднозначное. Переименовать в `POST /admin/reset-demo` и обязательно требовать явный параметр `?confirm=true`, чтобы случайно не дёрнуть.

**4. `PUT /profile` вместо `PATCH`.**
Сейчас используется PUT, но по-факту частичное обновление (несколько полей). Заменить на PATCH — семантически правильнее и уже согласуется с `PATCH /accounts/{id}` и `PATCH /cards/{id}`.

**5. camelCase vs snake_case в ответах — вперемешку.**
Примеры: `ttlSeconds`, `amountRangeRub`, `inOurBank`, `availableBanks` vs `from_account_id`, `access_token`, `is_primary`. Питон-конвенция snake_case выигрывает по количеству. Прогнать все ответы через snake_case (`ttl_seconds`, `amount_range_rub`, `in_our_bank`, `available_banks`) — станет консистентно.

## Что добавить

**1. `GET /accounts/{id}` и `GET /cards/{id}` — детали одной сущности.**
Сейчас фронт вынужден качать полный список и находить нужный `.find()`. Прямой эндпоинт разгрузил бы клиента.

**2. `GET /transactions/{id}` — JSON операция.**
Сейчас только `.../receipt` (HTML). Для модалки деталей операции пришлось бы искать в списке.

**3. `POST /auth/logout` — blacklist токена.**
Сейчас клиент просто выкидывает токен из localStorage, но JWT остаётся валидным до истечения. Для честного logout — таблица `revoked_tokens` и проверка в auth-middleware.

**4. `GET /statistics/monthly?month=YYYY-MM` — за произвольный месяц.**
Уже принимает `year` и `month` как query, но фронт этим не пользуется. Добавить в UI переключатель месяца в блоке инсайтов.

**5. `GET /accounts/primary` — узнать приоритетные.**
Сейчас есть только PUT для их установки. Полезно для UI-виджета «мой основной счёт».

**6. `POST /profile/avatar` — загрузка аватара.**
Пока в интерфейсе — только инициалы. С аватаром выглядит живее. Multipart, хранение файла в volume.

**7. `GET /transfers/exchange-preview?from&to&amount` — сколько получу.**
Сейчас `/rates` возвращает курсы, но клиенту приходится считать конвертацию самому. Дедупликация: пусть считает бэк.

## Логические штуки, которые стоит поправить

**1. `/helper/otp/preview` — требует авторизации.**
Значит его нельзя использовать для восстановления пароля. Мы сделали отдельный `/auth/password/reset-request`, который возвращает OTP в `test_hint`. Это работает, но `/helper/otp/preview` можно тоже разрешить без авторизации, если передан `?login=xxx` — тогда единая точка.

**2. `GET /transfers/recent-phones` — сейчас всегда возвращает top-3.**
Добавить `?limit=N` (макс 10) — для страницы «Все контакты» в будущем.

**3. Payments `/mobile` и `/vendor` — принимают `account_id`, но не `card_id`.**
В переводах уже добавили `from_card_id`. Логично и для платежей: пользователь выбирает карту в UI, а не счёт.

**4. `TransactionPublic` не содержит `card_id`.**
Модель БД содержит, схема — нет. Добавить, чтобы фронт мог фильтровать «операции по карте».

**5. Отсутствует `POST /accounts/{id}/close` в explicit endpoint.**
Сейчас есть `DELETE /accounts/{id}` — семантика РЕСТ ок, но пользовательский флоу «закрыть счёт» с проверками (баланс должен быть 0, нет активных карт) визуально понятнее через POST-action.

## Что убрать точно (мусор)

- `POST /helper/clear-browser` — не серверная задача.
- Роутер `/api/v1/dev/trace/*` — если не используется на dashboard'ах, скрыть через env-флаг `ENABLE_DEV_TRACE`.
- `admin/users/{id}/transactions` — если не используется UI-админкой, тоже спрятать до появления соответствующей страницы.

## Приоритеты (что делать в первую очередь)

1. **Добавить `GET /transactions/{id}` + `card_id` в `TransactionPublic`** — блокеры для полноценной страницы деталей операции и «операций по карте».
2. **Добавить `card_id` в payments-запросы** — единообразие с переводами.
3. **Переименовать `/helper` → `/dev` и скрыть в prod** — гигиена.
4. **snake_case во всех ответах** — большой refactor, но окупится единообразием.
5. **Остальное — по мере необходимости.**
