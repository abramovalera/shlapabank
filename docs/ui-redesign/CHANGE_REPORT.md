# Отчёт по переписыванию UI (v1)

## Что изменилось в интерфейсе

**1. Появился новый UI на React.**  
Старый интерфейс (папка `ui-mockup/`) остался — открывается по адресу http://localhost:8001/login. Новый UI живёт в папке `ui/` и открывается по адресу **http://localhost:8080/**. Работают оба одновременно, старый можно удалить в любой момент, ничего не сломается.

**2. Полностью новая главная страница.**  
Сверху крупный блок «Общий баланс». Рядом — курсы валют. Ниже слева новая карусель карт (одна активная карта + информация о её счёте + стрелки для перелистывания). Под каруселью — компактный список счетов, в каждом видно сколько к нему привязано карт. Справа — колонка с быстрыми действиями, лимитом на месяц и блоком поддержки.

**3. Появилась отдельная страница «Карты».**  
Новый пункт в верхнем меню. Показывает все карты пользователя крупными плитками, у каждой видно счёт, баланс и статус (активна / заблокирована). Есть кнопка «Выпустить карту» — открывается окно выбора счёта.

**4. Экран входа/регистрации переделан.**  
Стал компактнее и аккуратнее, минус лишние декоративные элементы.

**5. История операций.**  
Список сгруппирован по дням (Сегодня / Вчера / 25 июля...) и фильтруется по типу (Все / Расходы / Доходы / Переводы / Платежи).

**6. Переводы.**  
Три вкладки: между своими / по номеру счёта / по телефону. Форма перевода между своими работает полностью, остальные две пока показывают заглушку — их API готово, подключим следующей итерацией.

**7. Платежи.**  
Поиск сверху, сетка категорий с иконками (ЖКХ, мобильная связь, интернет и т.д.), список последних платежей.

**8. Профиль.**  
Слева карточка пользователя с аватаром-инициалами, справа список настроек (Личные данные / Безопасность / Уведомления / Внешний вид / Выйти).

**9. Единая шапка на всех страницах.**  
Логотип + меню (Главная / Карты / Переводы / Платежи / История) + аватар пользователя (кликабельный, ведёт в профиль) + кнопка выхода.

**10. Стиль в целом.**  
Плоский, минималистичный, светлая тема, тонкие границы, никаких градиентов и теней. Всё в едином дизайне.

## Что изменилось в логике / бэкенде

**1. Появилась сущность «Карта».**  
Раньше карт в системе вообще не было — были только счета. Теперь у счёта может быть несколько карт (дебетовая физическая, виртуальная, кредитная). Карта хранит: номер, последние 4 цифры, имя владельца, срок действия, платёжную систему (VISA / MIR / MasterCard), статус.

**2. Автовыпуск карты при открытии счёта.**  
Когда пользователь открывает новый счёт типа DEBIT, к нему **автоматически** выпускается дебетовая карта. У накопительных счетов (SAVINGS) карт не будет — они не для расчётов. Раньше открытие счёта карту не создавало.

**3. Тестовый клиент теперь с картами.**  
У встроенного `fullclient` при первом запуске к каждому его дебетовому счёту автоматически выпустится карта.

**4. Появились API-эндпоинты для карт:**
- получить все карты пользователя;
- получить карты одного счёта;
- выпустить новую карту к счёту;
- заблокировать / разблокировать карту;
- закрыть карту.

**5. Ограничение: максимум 5 карт на один счёт.**  
Больше не даст выпустить — вернёт понятную ошибку.

**6. В ответе по счёту теперь есть поле `cards_count`.**  
Раньше приходилось отдельным запросом узнавать, сколько карт привязано к счёту. Теперь эта цифра приезжает вместе со счётом — фронт может её сразу показывать.

**7. У операции появилось поле `card_id`.**  
Опциональное. В будущем будет заполняться при оплате картой, чтобы в истории было видно «списание с карты •••• 4021». Пока хранится, но заполняется только при новых операциях после апдейта.

**8. База данных мигрирует автоматически.**  
При первом запуске новой версии в существующей базе появится таблица `cards` и колонка `card_id` в `transactions`. Ничего вручную сбрасывать не нужно.

## Что стало удобнее для автотестов

**1. На всех интерактивных элементах проставлены `data-testid`.**  
Селениум / Playwright / Cypress цепляются по стабильному атрибуту, а не по классам, которые могут меняться при рестайлинге. Примеры: `login-submit-btn`, `card-toggle-block-42`, `history-tx-15`, `nav-cards`.

**2. Появился Swagger для карт.**  
Все новые эндпоинты видны на http://localhost:8080/docs — можно сразу писать API-тесты.

**3. Единая точка входа на 8080.**  
UI и API живут на одном порту (nginx проксирует `/api/` на бэкенд), так что автотесты работают без CORS-костылей.

## Как запустить

```bash
docker compose up --build
```

После сборки:
- **UI:** http://localhost:8080/
- **API + Swagger:** http://localhost:8080/docs
- **Тестовый клиент:** логин `fullclient`, пароль `FullClient1!`
