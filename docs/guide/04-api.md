# Работа с API

Все адреса начинаются с `http://localhost:8080/api/v1`. Запросы и ответы — JSON. Список всех адресов с полями — в [Swagger](tools/02-swagger.html).

## Вход

Вход — в два шага:

| Шаг | Запрос | Что передать | Что придёт |
| --- | --- | --- | --- |
| 1 | `POST /auth/login` | телефон и пароль | `challenge_id`, на телефон ушла SMS с кодом |
| 2 | `POST /auth/login/confirm` | `challenge_id` и код из SMS | `access_token` |

Дальше во всех запросах — заголовок `Authorization: Bearer <access_token>`. Кто вошёл — `GET /me`.

| Правило | Значение |
| --- | --- |
| Сколько живёт токен | 60 минут |
| Код из SMS | 4 цифры, живёт 5 минут, 3 попытки |
| Новый код | не раньше чем через 60 секунд — `POST /auth/login/resend` |
| Если снова вызвать `/auth/login` | прежний вход отменяется, работает только код из последней SMS |
| Таймеры | `resend_in_seconds` — через сколько секунд можно запросить новый код, `expires_in_seconds` — через сколько истечёт код; считаются по часам банка. Узнать их заново — `GET /auth/login/{challenge_id}` |
| Выход | на сервере его нет: токен действует, пока не истечёт |

Где взять код — страница [SMS](tools/01-sms.html).

## Счета и карта

| Что | Запрос |
| --- | --- |
| Мои счета | `GET /accounts` |
| Открыть счёт (до 3) | `POST /accounts` |
| Переименовать / закрыть | `PATCH /accounts/{id}` / `DELETE /accounts/{id}` |
| Виртуальная карта | `GET /card` — если карты нет, придёт `404` |
| Выпустить / сменить счёт карты | `POST /card` / `PATCH /card` |
| Реквизиты карты | `GET /card/requisites` |

## Операции

**Как проходит операция:**

1. Создаёте операцию — банк сразу проверяет всё: формат, счёт, получателя, сумму, хватает ли денег с комиссией, лимиты. Если что-то не так — ошибка, операция не создаётся.
2. Переводы и платежи ждут **код из SMS** (статус `WAITING_CODE`). Между своими и пополнение проходят сразу.
3. Вводите код (`POST /operations/{id}/confirm`) — банк ещё раз всё проверяет и проводит операцию.

**Найти получателя до перевода** (так делает интерфейс — показывает имя, банк и комиссию):

| Что | Запрос |
| --- | --- |
| По телефону | `GET /recipients/phone?phone=9000000001` |
| По номеру карты | `GET /recipients/card?number=2200010000000029` |

Ошибки — те же, что у самого перевода.

**Повторные запросы:** запросы одного клиента, которые что-то меняют, выполняются по очереди. Двойное подтверждение проведёт операцию один раз, второй ответ — `409` «Операция уже завершена».

**Статусы:**

| Статус | Что значит |
| --- | --- |
| `WAITING_CODE` | ждёт кода из SMS, деньги ещё не списаны |
| `DONE` | выполнена |
| `DECLINED` | отклонена — причина в поле `decline_reason` |
| `CANCELLED` | отменена клиентом (`POST /operations/{id}/cancel`) |

Код истёк — операция по-прежнему ждёт: запросите новый код (`POST /operations/{id}/resend-code`) или отмените её. Три неверных кода — операция отклоняется.

**Сумма** (`amount`) — например `"1500"` или `"1500.50"`: не больше 2 знаков после точки, больше нуля, без `1e3` и подобного.

**Порядок проверок** — если ошибок несколько, приходит первая: формат поля → счёт → получатель → сумма по тарифу → хватает ли денег → лимиты.

**История** — `GET /operations`, новые сверху. Фильтры:

| Параметр | Значения | Пример |
| --- | --- | --- |
| `type` | `OWN_TRANSFER` — между своими, `PHONE_TRANSFER` — по телефону, `CARD_TRANSFER` — на карту, `INCOMING_TRANSFER` — входящий, `MOBILE` — связь, `UTILITY` — ЖКХ, `TOPUP` — пополнение | `type=MOBILE,UTILITY` |
| `status` | `DONE`, `DECLINED`, `CANCELLED`, `WAITING_CODE` | `status=DECLINED` |
| `direction` | `in` — поступления, `out` — списания, `internal` — между своими | `direction=out` |
| `account_id` | id своего счёта | `account_id=1` |
| `date_from`, `date_to` | дата `ГГГГ-ММ-ДД`, включительно | `date_from=2026-11-01` |
| `limit`, `offset` | сколько вернуть (1–100, по умолчанию 20) и сколько пропустить | `limit=50&offset=50` |

Несколько значений — через запятую или повтором параметра (`type=MOBILE&type=UTILITY`). Регистр букв не важен: `type=mobile` = `type=MOBILE`. Операции, которые ждут кода, в истории не видны, пока не попросить `status=WAITING_CODE`.

## Тарифы и лимиты

| Что | Запрос |
| --- | --- |
| Комиссии и суммы по операциям | `GET /tariffs` |
| Лимиты: сколько потрачено и осталось | `GET /limits` |
| Поставщики ЖКХ | `GET /dictionary/providers` |
| Операторы связи | `GET /dictionary/mobile-operators` |

Сами тарифы и лимиты — в требованиях: [Тарифы и лимиты](requirements/07-limits.html).

**Типы в тарифах и в истории отличаются.** Тариф зависит от того, в какой банк уходят деньги, поэтому у переводов в `GET /tariffs` по два типа, а в истории — один:

| Тип в истории (`type`) | Тип в тарифах (`operation_type`) |
| --- | --- |
| `OWN_TRANSFER` | `OWN_TRANSFER` |
| `PHONE_TRANSFER` | `PHONE_OWN_BANK` — клиенту ShlapaBank, `PHONE_OTHER_BANK` — в другой банк |
| `CARD_TRANSFER` | `CARD_OWN_BANK` — на карту ShlapaBank, `CARD_OTHER_BANK` — на карту другого банка |
| `MOBILE` | `MOBILE` |
| `UTILITY` | `UTILITY` |
| `TOPUP` | `TOPUP` |
| `INCOMING_TRANSFER` | — (входящий перевод, без тарифа) |
